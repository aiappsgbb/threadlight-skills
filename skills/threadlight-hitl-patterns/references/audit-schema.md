# Audit trail schema

> Every action gate writes one audit event to Cosmos `case_audit` container.
> This is the canonical schema — handlers MUST conform.

## Container shape

| Property | Value |
|----------|-------|
| Container name | `case_audit` |
| Partition key | `/case_id` |
| TTL | `null` (never expire — audit is permanent) |
| Indexing policy | include `gate`, `gate_id`, `correlation_id`, `approval_id`, `actor.upn`, `timestamp`, `linked_rules[]/?` |

## Document shape

```json
{
  "id": "audit-{uuid4}",
  "case_id": "DEMO-CUST-00007",
  "gate": "approve",
  "gate_id": "GATE-001",
  "decision": "approved",
  "correlation_id": "corr-returns-20260510-084700",
  "approval_id": "apr-20260510-084723-0001",
  "policy_id": "TG-RET-003",
  "tool_name": "returns_apply_decision",
  "contract_sha256": "sha256:6d6bc7d6a1b4f6d0d0ef4f5f7f8e9a0b5c8d3e2f1a6b7c8d9e0f1a2b3c4d5e6f",
  "actor": {
    "upn": "analyst@northbank-demo.com",
    "displayName": "Jane Analyst",
    "objectId": "00000000-0000-0000-0000-000000000000"
  },
  "timestamp": "2026-05-10T08:47:23Z",
  "linked_rules": ["BR-001", "BR-007"],
  "agent_proposal": {
    "decision": "approved",
    "rationale": "Customer cleared all KYC checks; no sanctions hit; PEP score 0.12 (below threshold)",
    "tool_calls": [
      {"tool": "sanctions_check", "result": "no_match"},
      {"tool": "pep_score", "result": 0.12}
    ]
  },
  "human_edits": null,
  "rationale": null,
  "sla": {
    "deadline": "2026-05-10T12:47:23Z",
    "status": "met"
  }
}
```

`gate` remains the canonical UX taxonomy (`approve`, `reject`, etc.); `gate_id`
is the stable SPEC interaction identifier (`GATE-NNN`). The governed fields
`gate_id`, `correlation_id`, `approval_id`, `policy_id`, `tool_name`, and
`contract_sha256` are required only for a governed conditional tool release.
Existing ungoverned events remain valid and readable with the legacy audit shape
(`case_id`, `gate`, `decision`, `actor`, `timestamp`, `linked_rules`, ...).

For governed conditional tools:

- Create `correlation_id` before policy evaluation and preserve it through the
  card, Action.Submit, persisted approval, and runtime adapter.
- Generate `approval_id` when the approval is persisted, and return it with the
  original `correlation_id`.
- Resolve `policy_id`, `tool_name`, and `contract_sha256` from the enabled
  manifest that declared the governed tool.

## Per-gate field requirements

| Field | approve | edit-and-approve | reject | escalate | signoff | audit-view | request-info |
|-------|---------|------------------|--------|----------|---------|------------|--------------|
| `decision` | ✅ | ✅ | `declined` | `escalated_to: <role>` | `acknowledged` | `viewed` | `requested` |
| `agent_proposal` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `human_edits` | n/a | ✅ (diff) | n/a | n/a | n/a | n/a | n/a |
| `rationale` | optional | recommended | ✅ required | ✅ required | optional | n/a | ✅ required |
| `sla` | ✅ | ✅ | ✅ | ✅ | ✅ | n/a | ✅ |
| `escalation_target` | n/a | n/a | n/a | ✅ | n/a | n/a | n/a |
| `request_template` | n/a | n/a | n/a | n/a | n/a | n/a | ✅ |

## Reading the audit

The audit container is queried by:

- **Workspace UI** (audit viewer drawer / panel)
- **Continuous evals** — `foundry-evals` ACA job pulls these to compute
  KPIs (approval rate, escalation rate, SLA-met rate, etc.)
- **Compliance team** — direct Cosmos queries for regulator reports
- **Replay tooling** — to reconstruct what happened on a case

## Privacy

The `actor.upn` field IS a real UPN in production but should be a
synthetic UPN (`analyst@northbank-demo.com`) in demos. Generated by
`threadlight-demo-data-factory` via the universal "no real PII" rule.

Raw tool arguments/results remain excluded unless the SPEC explicitly selects
non-sensitive fields or hashes for audit, so `agent_proposal.tool_calls` should
store only approved summaries or hashes rather than full payloads.
