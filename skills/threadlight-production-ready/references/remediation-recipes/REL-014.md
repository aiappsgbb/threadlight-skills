## Target file
`evidence/crash-test-hosted.json`.

## Edit type
`insert`

## Edit recipe
1. Deploy the current image with `THREADLIGHT_SIMULATE_CRASH_AFTER_PHASE=0`
   (the long-running template exits with 137 after the first checkpoint, first
   attempt only), start a turn with `long_running_client.py start` and `follow` it.
2. From the container logs and a full replay (`GET /responses/{id}?stream=true`),
   write:

   ```json
   {"evidence": "hosted", "verdict": "recovered", "image": "<value of SERVICE_<AGENT>_IMAGE_NAME>",
    "agent_version": "<n>", "captured_at": "<ISO-8601 with offset>", "response_id": "<id>",
    "entries": [{"is_recovery": false}, {"is_recovery": true, "start_phase": 1}],
    "replay": {"response.created": 1, "response.in_progress": 2, "response.completed": 1}}
   ```
3. Redeploy without the variable. A new image needs a new record; records older
   than 90 days, from another image, or with `"evidence": "local"` (the offline
   harness) do not pass. Offline inventory (REL-009..013) is never live proof.

## Verification
Re-run threadlight: `python3 skills/threadlight-production-ready/scripts/production_ready.py --root <project>`. REL-014 flips to `pass` only for a hosted, recovered, fresh record whose `image` equals the current `SERVICE_*_IMAGE_NAME` in the azd env.
