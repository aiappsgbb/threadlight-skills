## What this checks

AGT-001 is the shared binding-level assurance predicate, not a policy-marker
lint. Legacy whole-agent `governed` verdicts and offline inventory never prove
deployed enforcement.

## Target file

`specs/governance-manifest.json` — emitted evidence, never hand-edit to green.

## Edit type

Manual, explicit staged verification; no automatic policy replacement.

## Edit recipe

1. Review the existing explicit governance contract. Preserve its framework,
   tool inventory, intervention points and exact requirement vocabulary. Do not
   bind extra tools, omit business actions or disable controls to obtain green.
2. Run `threadlight-govern --emit` to produce the current inventory at
   `specs/governance-manifest.json`. Resolve static/package gaps and run the
   mandatory pre-deploy `threadlight-governed-actions` gate.
3. After deployment, use `threadlight-safe-check`'s explicitly configured
   staging noop collector. Recollect when the manifest, image, policy, identity,
   environment or configuration changes, or receipts expire.
4. Leave unsupported business bindings/lifecycle points unverified. Noop proof
   belongs only to its reserved binding and `pre_tool_call`; never exercise a
   consequential business action just to satisfy readiness.
5. Unbound reads need no acceptance. Consequential/unknown unbound tools require
   a current per-tool acceptance and exact deployment/change scope, as documented
   in [pillar 2](../pillars/02-agent-governance.md).

## Verification

Re-run production readiness and the `readiness-proof` evidence gate. A pass
requires all selected bindings enforced in enforce mode, valid fresh scoped
live proof, zero unverified/bypassable coverage and no gaps. Missing tooling,
malformed receipts and legacy v2 remain unverified. No deployment enforcement
claim is created by this recipe, and no cloud command runs automatically.
