## Edit recipe

A returns supervisor may take three days to answer. No agent session survives
three days, and it should not try. The correct shape is therefore **not** "hold
the run" but: persist the pending decision, exit, and resume on an inbound
trigger that reconstructs state from the store.

Every component for this already exists — `threadlight-hitl-patterns` produces
the gate and audit trail, `threadlight-event-triggers` produces the ACA HTTP /
queue receiver with idempotency wiring, and the state store is already declared.
What is missing is the statement that they compose into a resume path.

1. For each gate in section 8, add two fields:

   ```markdown
   ### Supervisor escalation review
   - **Trigger**: BR-003 fires (refund > $250, serial-returner >= 0.40).
   - **Actor**: Returns supervisor
   - **Channel**: Teams adaptive card / workspace queue
   - **Timeout/SLA**: manual review < 24h.
   - **Resume trigger**: the approval webhook posts to the ACA HTTP receiver
     generated by `threadlight-event-triggers`.
   - **Rehydrated state**: the pending case is reloaded from Cosmos by
     `correlation_id` — consolidated case, risk rationale, policy citations and
     refund amount, so the resumed invocation needs nothing from the original
     process.
   ```

2. Name the store and the key, not just "state is persisted". The key is what the
   resumed invocation looks the work up by, and it is normally the same key
   HITL-006 uses as the idempotency key.

3. Declare what happens when the trigger never arrives. The SLA line says how long
   the wait is; say what fires at the end of it (auto-escalation, timeout denial,
   re-notification), otherwise the gate has no terminating condition.

4. Do not describe the resume path as holding an open session, a sleep, or an
   in-memory wait. If the spec says the run waits, the pilot loses the unit of
   work the first time the host recycles.
