## Target file
N/A — this fix runs the threadlight `threadlight-connect` leg. The connect leg reports INT-001 must-fix when a real integration tool's response does not conform (field-for-field, cardinality, requiredness) to the mock contract the pilot was built against. Remediation runs the leg (or its upstream fix) and refreshes `specs/connect-manifest.json`, whose shared envelope production-ready reads as gap evidence for `INT-001`.

## Edit type
`sibling-skill`

## Edit recipe
1. Inspect the conformance diff in `specs/connect-manifest.json` (`conformance.differences[]`) and the captured real sample.
2. Correct the contract mismatch at its source — usually the field mapping in the MCP server tool, or the `data-contract` extracted from the mock. Do NOT loosen the mock contract to hide a real gap.
3. Re-run the conformance check and re-emit the manifest with `threadlight-connect`.

   ```bash
   python3 skills/threadlight-connect/scripts/connect.py verify --tool <tool> --sample-file real_sample.json --emit
   ```

## Verification
Re-run threadlight: `python3 scripts/production_ready.py --target-rg <RG> --target-sub <SUB>`. INT-001 flips from `must-fix` to `pass` once `specs/connect-manifest.json` records `INT-001: pass` inside a `complete`, fresh envelope. A `partial`, stale, or `aborted` `specs/connect-manifest.json` keeps `INT-001` at `not-verified` (or `must-fix` on negative evidence) — an incomplete leg never inflates readiness.
