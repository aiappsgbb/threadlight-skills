A convincing explanation is not approval. A reused approval, the wrong role or a different action scope cannot satisfy the selected policy either.

Stop before the effect.Obtain valid approval; do not reinterpret a denial as success.

02Earn the claim

Three levels of evidence.
Three different claims.

The useful question is not “is it green?” It is “what ran, on which path, and what does that let us conclude?”

  1. Inventory / not enforcement

    Declared

    Inventory the selected bindings and author the policy.

    Configuration names the boundary.
    It does not prove enforcement.

  2. Execution / local only

    Executed locally

    Exercise LOCAL-14 and the exact native runtime / conformance paths.

    Separate executed results.
    Not hosted proof or certification.

  3. Hosted / scope-bound

    Observed after deployment

    Collect fresh, deployment-bound invocation evidence and independent observations.

    Collector scope: governance_probe_noop.
    Not business writes.

Where the runtime and release boundaries sit

Know the runtime boundary.

Native MAF supports selected tool/lifecycle and buffered-output controls. GHCP effect closure is limited to registered gateway action paths. Neither implies arbitrary tool or full-output coverage.

Know the release boundary.

The governance implementation is merged in PR #127. Some integrations use preview/alpha dependencies. This is not a GA guarantee; dated hosted evidence is historical, not a reusable readiness certificate.

03Beyond the action

Preview maturity · PR #128 merged · opt-in

Yesterday's result.
Today's deployment?

Bind the result to this agent, source and environment before reusing it.

Receipts establish local process provenance, not Azure attestation. Default assessment is local; native eval or Doctor requires separate approval.

Artifact validation, execution boundaries and readiness findings

What you gain

An agentops.yaml marker selects the agent. The adapter checks provenance, artifact hashes, freshness and native result/history consistency, then emits specs/agentops-manifest.json.

Existing eval and red-team consumers retain quality ownership. Production-ready reports residual AOPS-001 findings without duplicating matching canonical evidence.

What it does not do

The default assessment is bounded and local. It does not run paid evaluations, invoke Doctor, authenticate to Azure or provision resources. Native operations need separate, explicit approval through the existing CI/CD owner.

Receipts establish local process provenance, not Azure attestation. They do not replace binding-scoped runtime governance proof.

Integrated in main; preview is a maturity label. PR #128 is merged. Its integration evidence is local/offline, not a new live deployment or production certification.
