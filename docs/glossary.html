Glossary

The words used across these pages, in plain language. Where a term describes evidence, the definition also says what it does not prove.

The pattern Platform and operations Runtime governance Levels of evidence

The pattern

Skill
A reusable procedure written in Markdown, with optional scripts and references, that an agent loads when a task needs it. Threadlight's engineering skills guide a coding agent such as GitHub Copilot; the agent you build has its own business skills.
SPEC
The design document (specs/SPEC.md) written from your brief: the process, people, tools, data, value model and production posture. Later skills read the SPEC instead of asking again.
Microsoft Foundry
The Azure platform that hosts the models, the agent, its evaluations and its traces. Every agent Threadlight produces runs in Foundry.
Hosted agent
The default: the agent's code runs as a container that Microsoft Foundry manages. Threadlight never places the agent loop in application code; web apps and Container Apps only host the user interface, a thin proxy, tool servers or jobs.
Prompt agent
A Foundry agent defined only by instructions and a model. Allowed only for trivial cases and only on an explicit opt-in by the user, recorded in the SPEC.
MCP
Model Context Protocol: the open protocol the agent uses to call tools. When a pilot needs its own tool server, Threadlight hosts it on Azure Container Apps.
Human in the loop (HITL)
A person reviews or approves a step before it takes effect. For a governed action, the approval is authenticated, tied to that exact action and usable once.

Platform and operations

Citadel
The AI Citadel governance hub: a shared Azure API Management AI gateway in front of model calls, with access contracts. Optional: recommended when the customer already runs or is provisioning one. It governs access to models, not every downstream action.
Spoke
A pilot connected to a Citadel hub through an access contract. The pilot keeps its own resources; its model traffic goes through the hub.
OTel
OpenTelemetry, the tracing standard. The agent sends traces to Application Insights so they are visible in Foundry.
AgentOps
An optional, opt-in preview for operating evidence after go-live: telemetry, evaluations and change records for the deployed agent. A pilot does not need it.
Readiness assessment
The production-ready skill scores a pilot against 13 pillars and lists each gap with an owner. It identifies gaps; it does not certify production.

Runtime governance

These parts work together only for the actions you select. A policy file, a green test run or one governed action never makes the whole agent governed.

SAFE
Scope, Anchored decisions, Flow integrity, Escalation: the method used to define the business rules an action must respect and to select which actions to bind. It is a way of specifying, not a runtime component.
Binding
One selected consequential action tied to its policy, approval and audit rules. Evidence is collected per binding and never covers the whole agent.
Unbound read
A read-only tool call outside any binding. It keeps working without a policy decision.
PDP
Policy decision point: the component that decides whether a bound action is allowed, denied or needs a person.
ACS
Agent Control Specification: the policy engine Threadlight uses as the policy decision point (PDP). It evaluates Rego rules locally through Open Policy Agent (OPA).
PEP
Policy enforcement point: the native host or gateway in front of the action, which actually lets it run or stops it. What it enforces counts, not what a policy file says.
Agent Hooks
The host and interceptor contract, with its SDK, that lets the host intercept an agent's tool and lifecycle events and consult the PDP.
AGT
Agent Governance Toolkit: a toolkit of governance components Threadlight builds on. It is not an enforcement layer by itself and does not protect every tool automatically.
ASSERT
Assurance: testing the agent's behaviour and evidence. It is not an enforcement engine and does not authorize actions before they run.

Levels of evidence

Each level proves something different. A lower level never stands in for a higher one.

Offline inventory
What a static check of the repository finds. It shows what is declared, not what runs.
LOCAL-14
The local proof suite that runs the actual served application path and checks allow, deny, failure, approval and final-effect outcomes. Local evidence, not live evidence.
CTK
Conformance Test Kit: the upstream test vectors for the native governance packages, run locally against the unmodified published packages. Local conformance, not live enforcement.
Collector
The hosted probe that checks that a deployed governed path answers. It calls only the reserved governance_probe_noop action, so it proves the path is reachable, not that a business write is governed.
Live evidence
Observed on the deployed environment after this deployment, for the same image, identities and policy. Receipts from earlier runs do not carry over.
