Build your first governed workflow

Use one returns example to move from local prototype to an authorized hosted workflow. Practice an allowed recommendation, a blocked request and a human-reviewed handoff — never a payment.

What you need now
Copilot, a separate pilot repository, the reviewed catalog and synthetic cases. Start without Azure.
Who you need later
A platform owner, approved target and budget, a publisher, and a real Outlook reviewer.

01 Describe the decision

Inputs
Three synthetic cases: eligible, ineligible and supervisor-only.
People
You and the process owner review rules; Copilot drafts the foundation and SPEC.
Result
A reviewed SPEC checkpoint, not a deployed agent or new permissions.
Copy the local design prompt 
Use threadlight-design in Full mode for the two-tool returns MCP reference:
returns_get_case and returns_apply_decision. Record recommendations and
supervisor handoffs, never payments. With synthetic cases, capture the owner's
rules, reviewer, success measure and unresolved prerequisites.
Select microsoft-agent-framework, runtime_shape=agent, protocol=responses,
Foundry hosted and governed-tool-gateway; resolve actual capability signals
through the runtime policy, not a forced override. Stop at the SPEC checkpoint.
No Azure discovery, business-system calls, deployment or presentation work.

02 Prepare the handoffs

Inputs
The reviewed SPEC, intended tenant/index alias and named owners.
People
The platform owner confirms model, network, identities and signing prerequisites. Stay local when any are missing.
Result
An explicit prerequisite and access handoff. Do not copy keys or login caches into prompts.
Phase 2: people, isolation and required inputs →

03 Rehearse locally

Inputs
Set CATALOG to the reviewed catalog and PACKAGE_OUTPUT to an unused local directory.
People
Copilot helps package sources and inspect local checks; you compare the synthetic outcomes.
Result
source-package.json and matching file hashes. Source-only, not Azure enforcement.
: "${CATALOG:?Set CATALOG}" "${PACKAGE_OUTPUT:?Choose an unused PACKAGE_OUTPUT}"
python3 "$CATALOG/skills/threadlight-deploy/references/governance/package_returns_mcp.py" \
  --output "$PACKAGE_OUTPUT"

This command makes no Azure or model call and refuses an existing output directory. Optional model rehearsal needs a separate endpoint and call budget.

Phase 3: commands, hashes and local-test limits →

04 Authorize the exact deployment

Inputs
The reviewed target, model, change list, budget and exact permission assignments.
People
You authorize that scope. The platform owner registers the host, observes its identity and applies only pre-approved roles. Personal OAuth consent stays separate.
Result
The native hosted agent, separate services and a fresh signed binding. Stop before validation if any are missing.
Phase 4: use the complete deployment-authorization prompt →

05 Validate with a real person

Inputs
Fresh binding, approved synthetic cases and budget, reviewer availability and independent observation access.
People
The person decides in Outlook. You verify allow, deny, pending, exact same-session resume and replay; never invent an approval.
Result
Joined authorization and business-audit evidence for this deployment. Replay must not create another business effect.
Phase 5: exact arguments, human review and independent checks →

06 Hand off operations

Inputs
Current evidence, immutable image, release adapters and named operations owners.
People
The application and platform teams own release preparation. Release approval, action approval and business go-live remain separate.
Result
An operations/release handoff, not certification. Retain evidence before separately approved cleanup of new test-owned temporaries.
