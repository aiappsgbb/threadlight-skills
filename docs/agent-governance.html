Authority at the effect boundary

The model proposes.
The system authorizes.

A convincing answer is not permission to write. Trusted components decide which actions may produce effects, using identity, signed policy, business facts, required approval and durable evidence.

Keep the prototype fast. Opt into governance for selected consequential tools before enabling their effects. This is not a new mandatory all-tools layer and not a promise to control every aspect of an AI system.

Who can authorize a write?

Not the model. The trusted execution path.

The actual private path is Foundry hosted MAF → FunctionTool/MCP → governed gateway → separately authenticated backend → Cosmos.

  1. Proposal

    The model selects a declared tool and supplies arguments. Text, retrieved instructions and an operation ID are not credentials or consent.

  2. Identity and scope

    The host and MCP gateway authenticate the caller. Fixed targets and strict schemas prevent the model from choosing an arbitrary HTTP destination.

  3. Policy and facts

    ACS evaluates Rego through OPA. Signed fresh policy, observed deployment and trusted business facts bind the exact proposal and ETag.

  4. Approval and receipt

    When required, an authenticated human decides. A one-use grant and central durable audit ACK must exist before the effect. Denial stops here.

  5. Independent writer

    A different identity calls the backend. It checks current state again and atomically replaces the case plus creates its decision audit.

  6. Bounded result

    Return the actual outcome. Reconcile native calls against independent records. A post-effect failure cannot be described as a rolled-back write.

Checks must survive waiting. Credentials, retries, connection pools and TLS can delay a send. The owned transports recheck authorization at the send boundary. Native trace/baggage propagation is accepted only when it matches the exact active SDK context; authorization, target, body and idempotency checks remain strict.

The read tool takes a separate authenticated route and remains unbound to ACS. Optional read-audit persistence is disclosure accounting, not permission to mutate.

Separate responsibilities, not interchangeable security labels
  • SAFE is the method; ACS/Rego is the policy decision point.
  • Agent Hooks is the host/interceptor contract. The selected host or gateway is the enforcement point; AGT is the toolkit; ASSERT is assurance.
  • Agent Identity, reviewer, control plane, gateway, downstream caller, database writer and publisher have distinct responsibilities. The agent has no database-write or signing role.
  • Private networks restrict reachability; output guardrails constrain supported returned content. Neither replaces authorization of the exact business effect.

Scoped end to end.
Not controlled in every respect.

  • Trusted computing base: reviewed code, the trusted host, identity injection, publisher, verifier, clocks, stores and independent backend. This is not a defense against a malicious administrator replacing those components.
  • Limited inventory: two exposed tools, one selected write. No arbitrary shell or HTTP tools are offered. No claim of chain-of-thought control, all-framework support, complete provider-tool interception or exhaustive bypass resistance.
  • Production is a separate decision: recovery drills, load/SLO behavior, privacy, organizational compliance and accountable risk owners need additional evidence. Public lab exceptions are not production defaults.
  • CI is not all green: three native dependency tests are in the unit lane and remain a separate wiring blocker. Documentation tests and one successful binding do not erase it.
  • No scope transfer: OBO A-to-B, private human completion and email automation remain unproved. Prototype speed and an advisory scorecard are not go-live authorization.
