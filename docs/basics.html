Skill-based agents / the Threadlight pattern

Agents use skills.
To build. To operate.

Skills give an agent reusable procedures. Threadlight's engineering skills help a coding agent create the project. The resulting process agent uses a separate set of business skills to carry out the work.

See how an agent uses skills ↓

01 / The skill-based agent

A library of procedures.
An agent to coordinate them.

A skill is a reusable instruction package: when to use it, what it needs, the procedure to follow and the result to produce. Its entry document is SKILL.md; supporting code, references and templates are optional.

A prompt gives one request. A skill-based agent uses a library of focused procedures to handle many requests. The same format supports different procedures and outputs—whether the agent is building software or working on a business case.

INSIDE THE PACKAGE

A document the agent can use.
With support when needed.

SKILL.mdPlain-text Markdown
Name + description
Identify the skill and when it is relevant, so the agent can select it for the task.
Procedure + boundaries
Explain the steps, expected inputs and outputs, required tools, and when to stop or hand off.
Optional supporting files
  • scripts/Code for repeatable work or validation.
  • references/Rules, schemas and deeper guidance.
  • assets/Templates and materials to reuse.

Readable instructions plus optional supporting files—not a standalone executable. The host must provide the tools needed to use the package.

INSIDE THE RUNNING APPLICATION

The agent coordinates.
The parts have different jobs.

Agent

The application that uses instructions, a model and tools to work toward a goal. It examines results and continues or asks for help.

ModelINTERPRET

Interprets context and proposes responses or actions. It can be wrong.

SkillGUIDE

Supplies the reusable procedure: what to check, how to proceed and when to escalate.

ToolPERFORM

Callable code that reads data or performs a permitted operation in a system.

The skill guides. The tool performs. A return-policy skill tells the agent what to assess; an order tool retrieves the facts. Backend controls decide which operations are allowed.

02 / Two skill sets, different responsibilities

One assistant builds it.
Another runs your process.

A coding assistant such as GitHub Copilot uses Threadlight's engineering skills to turn your brief into a project. The resulting process agent gets its own business skills and connected tools, not a copy of the engineering playbooks.

The value is a connected path from an agreed specification to runnable code and evidence you can inspect, rather than just a generated answer. A specification is the written agreement about what the process must do and what stays human.

WHERE AUTO FITS

Who coordinates the building steps?

This orchestration—the coordination of what happens next—is supported by threadlight-auto. It is a planner: it inspects existing project files and chooses run, skip or stop. The coding assistant or an assigned worker performs the work. It is not the returns assistant, and it does not silently approve deployment or paid operations.
